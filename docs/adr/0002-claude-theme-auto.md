# Let Claude Code auto-detect background via OSC 11

`config/nvim/lua/plugins/ai.lua` previously launched Claude with an explicit `--settings '{"theme":"<light|dark>"}'` computed from `vim.o.background` at launch, to suppress Claude's own OSC 11 probe — an older Claude version's probe leaked `11;?` into the input prompt because nvim's `:terminal` didn't consume the response. The workaround baked Claude's theme in at launch, so any subsequent `vim.o.background` flip (from `<leader>bg` or the `FocusGained` OSC 11 re-detect in `appearance.lua`) stranded Claude in the wrong palette — Claude painted dark-theme foregrounds onto nvim's light Normal bg and dim secondary text became unreadable. Current Claude Code's `/theme auto` probes libvterm cleanly and re-detects continuously, so we drop the override and let Claude follow nvim's bg the same way the rest of the UI does; if the leak ever recurs, restore the override in `ai.lua` with `"auto"` (not a baked-in light/dark) so theme tracking still works.
