# Take the nvim colorscheme's hues from the terminal's ANSI palette

`config/nvim/colors/claude.lua` takes every hue from the iTerm2 "Default" profile: background, foreground, cursor and selection per light/dark mode, and the ANSI 16, which eza (behind `ls`) paints with. Before, its palette came from Claude Code's own theme tables, so nvim looked unlike the shell around it. A role uses the slot `ls` shows for the same thing. iTerm's "Use Bright Bold" renders eza's bold names in the bright slots, so `Directory` and neo-tree directory names are bright blue `#a7abf2`. The ANSI 16 are the same in iTerm's light and dark modes, so both tables share one set of hues and differ only in the neutrals (cursorline, surfaces, diff and search tints), which are small offsets from each mode's background. This is a literal match, and in light mode it means the same low-contrast greens, yellows and cyans that `ls` shows on `#fafafa`. A darker light-mode table would read better but would no longer match the terminal. If the iTerm palette changes, update the `ansi` table and the per-mode `bg`/`fg`/`cursor` values to match. The scheme keeps the name `claude` so `lua/appearance.lua` needs no change.
